# Security Policy

## Supported versions

Security fixes are applied to the default branch. This is an active portfolio project; no long-term support or service-level agreement is offered.

## Reporting a vulnerability

Please do not publish exploit details, credentials, personal data or sensitive logs in a public issue or pull request.

If GitHub private vulnerability reporting is enabled for this repository, use the repository's **Security → Advisories → Report a vulnerability** flow. Otherwise, contact the repository maintainer through a private channel listed on their GitHub profile and include:
- affected commit or version,
- impact and preconditions,
- minimal reproduction steps,
- a suggested mitigation if known.

Allow reasonable time for triage and remediation before public disclosure. Do not test against systems or data you do not own or have explicit permission to assess.

## Scope and expectations

This policy does not imply that the application is certified, independently audited, or production-ready. Never submit real credentials, customer datasets or production identifiers in reports.
